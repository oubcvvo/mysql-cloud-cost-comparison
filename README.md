## 架构决定你为几份资源买单

单节点只部署一个数据库节点，账单对应一份资源，这是它门槛最低的直接原因。代价也直接：没有主从热备，宿主出问题服务就中断。测试库、内部报表、个人项目这类「挂了能等」的场景，单节点够用。

双节点是主从热备结构，官方文档描述为实时热备加故障自动切换。对任何有真实用户的业务，这基本是底线配置——你付的是第二份资源的钱，换的是故障时业务能自己恢复。

三节点提供更高一级的冗余，规格和双节点共用通用型、独享型两张表。除非业务中断的损失远大于服务器成本，否则不必上三节点。

云盘版是另一条产品线，2核4GB 起步，最高能到 384核，存储 20GB 到 32TB。它适合规格需求跨度大、又要存储弹性的场景，不适合作为「找最便宜」的入口。

## 双节点经济型：便宜的原因和代价都写在硬盘上

想用最低成本拿到双节点高可用，经济型是唯一入口。它只有四档配置，硬盘容量跟规格绑定：1核2GB 配 50GB、2核4GB 配 100GB、4核8GB 配 150GB、8核16GB 配 200GB。

这意味着容量预估要一次到位。通用型可以在 25GB 到 3000GB 之间自由填写，经济型不行，你只能在四个固定档位里选。如果数据量半年内会超过当前档位容量，直接跳到下一档，或者一开始就选通用型，比后期迁移省事。

IOPS 同样是固定值：1核2GB 是 2000，2核4GB 是 4000，4核8GB 是 8000，8核16GB 是 20000。博客、小型电商后台、SaaS 的早期版本，这个性能够用。写入密集的业务，比如频繁批量导入或高并发订单，2000 IOPS 会先成为瓶颈，省下来的钱会以另一种方式还回去。

## 单节点基础型：最低门槛，但小容量盘的性能账要算清楚

单节点基础型是全场起点，1核1GB、20GB 存储就能开通，存储上限可以扩到 30000GB。它有三种盘可选，性能公式完全不同：

- 高性能云硬盘：随机 IOPS = min{1800 + 8 × 容量(GB), 6000}，吞吐上限 150MB/s
- SSD 云硬盘：随机 IOPS = min{1800 + 30 × 容量(GB), 26000}，吞吐上限 260MB/s
- 增强型 SSD 云硬盘：随机 IOPS = min{1800 + 50 × 容量(GB), 50000}，吞吐上限 350MB/s

公式里有个 1800 的基数，所以小容量时三种盘的差距没有想象中大。20GB 盘：高性能云硬盘约 1960 IOPS，SSD 约 2400，增强型 SSD 约 2800。容量越大差距越明显，500GB 时分别是 5800、16800、26800。

也就是说，只买几十 GB 小盘的话，盘型对性能的影响有限，真正拉开差距的是容量上了百 GB 之后。选盘时按实际容量和数据增长预期套一遍公式，别只看盘型名字。

## 通用型和独享型：什么时候值得加钱

通用型买的是弹性：规格从 1核1GB 一直到 80核690GB，存储 25GB 起，最高可到 12000GB，规格档位多、存储可自由填。但「通用型」三个字不代表性能一定更强——1核1GB 的最大 IOPS 只有 1200，比经济型 1核2GB 的 2000 还低。选通用型要看具体规格，别只看名字。

独享型 2核16GB 起，起步 IOPS 就有 8000，资源不与其他实例共享，适合对性能稳定性敏感的中大型业务。小项目买独享型，属于把钱花在了用不到的地方。

## 跨厂商比价时，怎么判断「真便宜」

不同云厂商的 MySQL 报价结构不一样，直接拿两家的最低价对比，很容易得出错误结论。有三个对齐动作值得做。

规格对齐。拿单节点的价格去比对方的双节点高可用版，比出来的「便宜」没有意义。先确认对方报价对应哪种架构、几个节点。

盘型对齐。同样标注「100GB 存储」，高性能云硬盘和增强型 SSD 的 IOPS 能差好几倍。问清楚报价里含的是哪种盘。

计费口径对齐。包年、按量、首年优惠和续费价要分开看。有些低价只适用于首年或特定活动期，续费回到原价。

三项对齐之后再比总价，才是同一件事的比较。

## 常见问题

**1核1GB 的 MySQL 能用于生产吗？**
技术上可以，单节点基础型就能开通。但它没有热备，宿主机故障会直接导致中断。有真实用户的业务，建议从双节点经济型起步。

**经济型的硬盘可以自己选容量吗？**
不能。四档规格分别固定搭配 50GB、100GB、150GB、200GB，无法像通用型那样在 25GB 到 3000GB 之间自选。选型时按未来一年的数据量预估。

**读多写少，怎么扩容最省钱？**
加只读实例，而不是把主实例升到更高规格。只读实例有独立地址，可以分担读请求，按需增加即可。

**单节点以后能升级规格吗？**
可以，腾讯云支持一键升级到更高性能和容量的规格，升级过程不影响业务正常访问。
